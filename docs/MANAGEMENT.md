# 管理与版本规范

## 日常维护

- GitHub `main` 是已采用计划；聊天中的建议在回写前只是讨论。
- 每周一次简短复盘，每月末一次阶段复盘；阶段转换、基线完成和考试后另做复盘。时区为 Asia/Shanghai。
- 周复盘使用 `reviews/YYYY-MM-DD-weekly.md`，月复盘使用 `reviews/YYYY-MM-monthly.md`。没有数据就写“未测”，不推断进步。
- 每次继续管理时先读取 README、路线、最新复盘、CHANGELOG 与当前远端版本，再修改，避免覆盖其他会话工作。
- 后续可直接在聊天中说“按本仓库做本周复盘”并提供脱敏摘要。助手整理、检查并提交已授权范围内的常规更新；新目标、报名、付费、数据迁移或公开范围变化须先确认。
- 本仓库不设置自动定时任务，不承诺离线运行期间主动更新。周期规范由学习复盘触发执行。

## 版本更新

首次正式提交和标签为 **v1.1.0**。此前讨论只是历史背景，不虚构 v1.0.0 提交或成绩。

| 变化 | 版本规则 | 例子 |
|---|---|---|
| 错字、澄清、流程修正，目标和阶段不变 | PATCH：v1.1.1 | 修正模板措辞 |
| 新增基线结论、单科目标、阶段安排或实质训练方法 | MINOR：v1.2.0 | 测试后调整时间配比 |
| 核心考试目标、用途或整体路线发生重大重设 | MAJOR：v2.0.0 | 改变目标考试窗口与目标体系 |

日常复盘可单独提交，不必每次打版本标签。每次正式发布同步更新 README 当前版本、相关计划、CHANGELOG；重大决策新增 `docs/decisions/NNNN-topic.md`，注明原因、证据、影响与复查条件。标签只创建一次，不移动旧标签；修正用新版本。

## 发布检查与回退

1. 只暂存明确列出的 Markdown 和模板，检查文件内容、差异和提交作者，排除私密材料及第三方全文。
2. 检查相对链接、日期、版本一致性、未确定事项和事实证据；空模板不能当测试结果。
3. 提交说明概括实际变化，例如 `docs: record weekly review` 或 `docs: release v1.2.0 after baseline`。
4. 推送后读回远端提交；正式版本创建同名标签和 Release，检查匿名可访问。
5. 普通内容错误用反向提交恢复，并发布修正版；不抹掉决策历史。隐私泄露不能靠删除当前文件解决：立即停止扩散，处理历史清除，凭据泄露须撤销凭据，再核验公开面。

## 数据边界与证据

原始写说样本、私有词汇库、日志和导出保留在仓库外；`.gitignore` 只是辅助，不能代替人工审查。公开复盘只放必要的匿名汇总。禁止从私有仓库复制完整目录或 Git 历史。

状态用 PASS（已验证）、FAIL（断言不成立）、BLOCKED（缺少前提）、INTERRUPTED（中断未验证）。注明日期、自动检查/人工评估/外部摘要的区别、证据来源和局限；AI 估分与自评不等于官方成绩。
