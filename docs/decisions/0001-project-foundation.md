# 0001：公开独立仓库与分阶段学习

日期：2026-11-10 · 状态：已采用 · 首发版本：v1.1.0

## 本地问题与授权

需要把已确认的雅思路线从聊天沉淀为可长期维护、可追踪变更的公开版本。用户已授权审计既有仓库、选择合适方案并公开发布；不得公开既有私有词汇库或个人敏感资料。验收为文档完整、首次提交与标签 v1.1.0、匿名可访问。

## 既有仓库审计与方案比较

已通过 GitHub 连接器和已登录命令行列举本人仓库（返回少于请求上限），按名称和描述筛选学习相关项目；另读取已有雅思词汇自动化项目的 README 确认范围。未发现用于整体雅思路线管理的合适既有仓库。

方案 A：扩展现有词汇自动化项目。优点是少一个仓库；缺点是学习计划与工具代码、验收周期混杂。

方案 B：新建独立公开学习仓库。优点是文档轻量、计划版本清晰、无需迁移私有历史；代价是需要维护一个独立入口。采用 B。

私有学习知识库仅作存在性和范围判断，保持原可见性，不复制其内容或历史；其他听力与字幕工具也不适合作为总计划中心。公开记录不列出私有仓库地址。

## reuse / adapt / avoid

- reuse：沿用已有自然输入、对话和 Anki 学习工作流；复用 Git 提交、标签、GitHub Release 与 Markdown，无额外依赖。
- adapt：为当前 5.5 目标、时间预算和待测基线整理路线；从已确认的文章分析吸收训练闭环，保留证据边界。
- avoid：私有历史迁移、原始个人资料公开、另造学习系统、自动改动词库、速成承诺和未核实签证结论。

这是文档治理任务，不涉及非平凡软件开发，故按比例跳过库选型和生态研究；不引入第三方代码或复制文章全文，也不擅自选择内容开源许可证。

## 实施与后续

顺序：审计—脱敏起草—链接和内容检查—首次提交—公开建库—推送标签与 Release—匿名访问核验。纯 Markdown 架构，MVP 包含目标、路线、决策、变更、管理、基线及复盘模板。

下一步先完成四科基线，再确定单科目标。考试类别、基线和签证要求仍未解决，不把建库成功写成学习达标。回退使用反向提交；既有仓库可见性和内容不变。
